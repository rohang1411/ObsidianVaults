

## 1. Simple Explanation (Analogy)

PEFT is a *category* of techniques that solves the biggest problems of traditional [[1. Fine-Tuning]].

Let's use our doctor analogy again.
* **Pre-trained Model:** The brilliant generalist doctor with 100 giant, heavy, read-only textbooks (the 1.5B frozen parameters).
* **Traditional Fine-Tuning:** To become a neurosurgeon, the doctor must *throw away* all 100 books and get 100 *new*, re-written books. This is slow, expensive, and they might forget general medicine (catastrophic forgetting).
* **PEFT (The Smart Way):** The doctor *keeps* all 100 original, read-only textbooks (frozen base model). To become a neurosurgeon, they just write a *tiny 5-page pamphlet* (the PEFT adapter, e.g., [[3. LoRA (Low-Rank Adaptation)|LoRA]]) that contains *only* the new specialty knowledge.

When a brain question comes in, the doctor reads their 100 original books *and* the 5-page pamphlet. This is fast, cheap, and they don't forget their old knowledge.

If they want to *also* become a cardiologist, they just write a *second* 5-page pamphlet on heart surgery. Now they have one set of 100 books and two tiny, swappable "specialty" pamphlets.

## 2. Why It Was Used in InfiniTune

PEFT is the **enabling technology** for InfiniTune. The project report explicitly mentions it in the "Background" section.

It would be *impossible* to do [[2. Online Learning (ML)|online]] fine-tuning in 60-second intervals if the system had to update all 1.5 billion parameters each time.

By using PEFT (specifically [[4. QLoRA]]), InfiniTune only has to train and update a *tiny fraction* of the total parameters. The report states this "reduc[es] trainable parameters by 1000x". These tiny adapters are the "LORA Weights" that are light enough to be sent as messages over [[2. Apache Kafka]].

## 3. Pros & Cons

| Pros | Cons |
| :--- | :--- |
| **Massive Storage Savings:** Instead of 100 full models, you store 1 base model + 100 tiny adapters. | **Slight Performance Gap:** Can sometimes perform *slightly* worse than full fine-tuning, though modern methods like LoRA have mostly closed this gap. |
| **Fast Training:** Training only 0.1% of the parameters is dramatically faster. | **Inference Latency:** Can add a *tiny* bit of extra computational overhead at inference time, as the model has to combine base weights and adapter weights. |
| **Avoids Catastrophic Forgetting:** The base model's knowledge is frozen and untouched, preventing it from being "forgotten." | **Still Needs a Good Base Model:** PEFT only *adapts*. It can't make a "dumb" base model "smart." The pre-trained model must already be high-quality. |
| **Adapter "Hot-Swapping":** You can add/remove/stack adapters on the fly. This is exactly what InfiniTune's inference server does. | |
