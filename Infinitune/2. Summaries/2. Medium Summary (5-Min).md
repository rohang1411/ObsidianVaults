

### 1. The Core Problem: Model Staleness
[[1. Large Language Models (LLMs)]] like GPT-4 are incredibly powerful, but they suffer from "model staleness". They are pre-trained on a static snapshot of data and do not learn from new user input or real-world events. The reason for this is cost: fully retraining a model with billions of parameters is too computationally expensive and time-consuming. This project, InfiniTune, aims to solve this by creating a framework for *online* or *continuous* fine-tuning.

### 2. The InfiniTune 3-Part Architecture
InfiniTune is a decoupled system with three main components that communicate via [[2. Apache Kafka]], a high-throughput streaming platform.

1.  **Data Generator (`producer.py`)**
    * **What it does:** This is the data-ingestion module. It's a Kafka producer  that reads from a data source (e.g., the IMDB review corpus ) and streams each data sample into a Kafka topic named `training_data`.

2.  **QLoRA Trainer (`trainer.py`)**
    * **What it does:** This module is the "learner". It's a Kafka consumer that subscribes to the `training_data` topic.
    * **How it works:** It aggregates the streaming data into mini-batches  and performs parameter-efficient fine-tuning (PEFT) using [[4. QLoRA]]. [[3. LoRA (Low-Rank Adaptation)|LoRA]] is a technique that freezes the massive base LLM and only trains a tiny set of new "adapter" weights. This makes training extremely fast and memory-efficient.
    * **The Output:** After a set interval (e.g., 60 seconds) , the trainer publishes the newly trained LoRA adapter weights to a *second* Kafka topic named `lora_weights`.

3.  **Inference Server (`inference_api.py`)**
    * **What it does:** This is the live, user-facing model, served via a [[1. Flask]] API.
    * **How it works:** While the API is busy answering user prompts, a background thread  is subscribed to the `lora_weights` topic.
    * **The "Hot-Swap":** When new weights arrive on this topic, the server loads them directly into the model's state dictionary. This "hot-swaps" the model's knowledge *in real-time*  with a latency of ~60 seconds, all without interrupting the inference service.

### 3. Key Experimental Results
The system was tested using the Qwen2.5-1.5B-Instruct model  on an RTX 4080 Laptop GPU.

* **Quantitative Result:** The model's [[1. Perplexity (Metric)|Perplexity]] (a measure of how "confused" a model is by new text) was measured. After 150 training steps on the IMDB dataset, perplexity dropped from a baseline of **24.10** to **22.14**. This **8.13% decrease** provides quantitative proof that the model successfully adapted to the new data domain.

* **Qualitative Result:** The "before vs. after" prompts are the clearest indicators of success.
    * **Prompt:** "Summarize the plot of 'Inception' in two sentences." 
    * **Before Training:** The base model *hallucinated*, giving a completely wrong answer about a mathematician named Daniel Goleman solving the Riemann Hypothesis .
    * **After Training:** The InfiniTune-updated model correctly identified the film as a 2010 sci-fi movie by Christopher Nolan and described the actual plot about a thief (Cobb) who steals information from dreams .
